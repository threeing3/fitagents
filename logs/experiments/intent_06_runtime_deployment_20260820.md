# Intent 06 独立推理服务部署验证

## 实验动机

将已通过离线发布门禁的 Qwen3-4B QLoRA 意图适配器部署为独立 GPU 推理服务，并验证 FitAgent 的“确定性规则 → 本地适配器 → DeepSeek 回退”三层链路真实可运行、可观测且安全规则始终拥有最终权威。

## 冻结范围

- 实验：`intent_qwen3_4b_20260817`
- 任务：`runtime-service-smoke-v1`
- 实例：北京 B 区 297 机 `2fa646b3c3-9b548d76`
- GPU：RTX 4090 24GB × 1
- 预算上限：5 元；预计 45 分钟内完成
- 底座、适配器、数据集和离线指标不变，本轮不重新训练
- 推理服务密钥只进入远端进程环境和本地临时请求环境，不写入代码、命令记录、日志或 Git

## 验收条件

1. CUDA、磁盘和 Python 预检通过。
2. 发布清单和适配器校验通过。
3. `/health/live` 与 `/health/ready` 通过。
4. 无鉴权分类请求返回 401。
5. 鉴权请求返回合法 `IntentDecisionV2`。
6. 危险输入经主应用合并后不低于规则风险等级。
7. 主应用客户端真实调用成功，并记录来源、模型版本、耗时与用量。
8. 服务不可用或超时时能进入受控回退，不绕过规则安全边界。

## 执行命令与步骤

1. 冻结 `runtime-service-smoke-v1`，预算上限 5 元，禁止无卡模式和替换实例。
2. 确认 297 机当前 GPU 容量不足，保持关机，没有产生本轮费用。
3. 本地补充客户端细分失败状态、适配器回退来源、真实规则覆盖原因和分阶段耗时。
4. 扩展 Agent Lab 单例诊断，展示规则、适配器、DeepSeek 和最终来源四个阶段。
5. 新增 `python -m algorithm.inference.verify_service` 部署验收程序。
6. 执行后端定向测试、Ruff、前端类型检查、组件测试和生产构建。
7. GPU 恢复后启动 `runtime-service-smoke-v1`；服务在模型加载前因 `langchain_core` 缺失退出，显存占用为 0 MiB。
8. 根因是轻量推理服务从线上分类模块导入意图枚举，形成不必要依赖；将枚举迁移到无线上依赖的共享模块，准备新的 v2 运行。

9. 创建代码快照 `ad95f2d14e124b68f9499e122930b8d4d2761e32`，在新运行 `runtime-service-smoke-v2` 中启动服务并完成内网验收。
10. 接受 AutoDL 自定义服务补充协议，将服务迁移到平台支持的内部端口 6006，并建立 HTTPS 公网映射。
11. `runtime-service-public-v1` 因新 Shell 未恢复底座和适配器路径，在参数解析阶段退出；使用显式绝对路径创建新的 `runtime-service-public-v2`，没有覆盖失败记录。
12. 通过公网运行服务验收和 FitAgent 主应用客户端验证，下载脱敏报告后优雅停止服务并关闭 297 机。

## 实验结果

- 后端定向测试：25 passed；共享意图目录修复后的定向回归：12 passed。
- Ruff（Python 静态检查）通过。
- 前端 TypeScript（前端类型系统）类型检查通过，组件测试 1 passed，生产构建通过；主 JavaScript（浏览器脚本）产物 198.41 kB，gzip（压缩格式）后 64.92 kB。
- `runtime-service-smoke-v1`：失败。服务在加载模型前因不必要的 `langchain_core` 依赖退出，GPU 显存占用 0 MiB；完整堆栈保留在独立运行目录。
- `runtime-service-smoke-v2`：内网验证通过。就绪检查返回 200，模型占用约 4463 MiB 显存；服务验证 5/5 通过，客户端真实调用成功，耗时约 3099 ms，输入 123 Token（文本编码单元），输出 47 Token，超时路径正确返回 `timeout`。
- `runtime-service-public-v1`：失败。新 SSH（安全远程登录协议）Shell 中路径变量为空，启动参数缺少值；失败发生在模型加载前，GPU 占用为 0，日志独立保留。
- `runtime-service-public-v2`：通过。AutoDL 内部 6006 端口的 HTTPS 映射可访问；存活、就绪、未授权拒绝、安全样例结构和风险样例结构共 5/5 通过，总验收耗时 7464 ms。
- FitAgent 的 `IntentInferenceClient`（意图推理客户端）经公网成功调用适配器，状态为 `available`，耗时 3781 ms，输入 123 Token，输出 47 Token；人工延迟服务触发 `timeout`，验证了受控回退。
- 公网分类接口要求 Bearer Token（请求身份令牌）；实验密钥只存在于进程环境，没有进入代码、Git 或下载报告。
- 本轮证明独立推理服务可以真实部署和接入，但该地址是按量 GPU 实例上的临时端点。验证结束后 297 机已关机，因此不声明当前持续在线。

## 失败原因与结论

- 两个失败运行分别暴露了“推理契约耦合线上依赖”和“远端命令依赖临时 Shell 变量”问题；两者均通过新运行修复，原始失败日志未覆盖。
- 最终运行满足存活、鉴权、结构、安全样例、公网客户端和超时回退门禁，可以作为 FitAgent 分层意图架构的真实部署证据。
- 297 机仅关机，未释放实例；远端模型、适配器和全部运行目录均保留。

## 下一步计划

- 服务端使用 `INTENT_INFERENCE_KEY` 注入推理密钥；FitAgent 应用端分别通过 `ADAPTER_INFERENCE_KEY` 和 `ADAPTER_INFERENCE_URL` 配置同一密钥与 HTTPS 地址，均不写入版本库。
- 若需要长期在线演示，应选择常驻 GPU 服务或建立按需启动流程，并单独记录费用、可用性和 P95（95% 分位）延迟。
- 在 Agent Lab（智能体实验室）中继续展示规则判定、适配器判定、DeepSeek 回退、最终决策来源和安全覆盖原因。
