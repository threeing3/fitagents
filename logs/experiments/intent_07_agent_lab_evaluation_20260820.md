# Intent 07 Agent Lab 批量评测展示

## 实验动机

将已经审核并发布的 120 条隔离挑战集结果接入 Agent Lab，使单条运行时诊断与批量离线证据同时可见，并明确区分安全基线、质量上限、成本折中和本地适配器候选。

## 修改内容

- 新增只读意图评测摘要接口，只返回聚合指标，不返回用户消息或逐样本预测。
- 对比 Rules v2、DeepSeek 全量调用、规则与 DeepSeek 混合路由、Qwen3-4B QLoRA 四条路径。
- 展示精确通过率、风险得分、模型调用次数、P50/P95 延迟、训练隔离状态和结论限制。
- 保留单例实时决策轨迹，批量指标不由实时请求改写。

## 执行命令与实验步骤

1. 读取三份已发布的聚合报告，设计无原始样本的公共响应结构。
2. 实现后端摘要接口、前端类型、请求函数、四路径对照卡片和响应式样式。
3. 首次运行后端定向测试时，新增测试错误地用字符串搜索检查 `user_message`，与安全元数据字段 `user_messages_exposed` 冲突，产生 1 个测试失败。
4. 同一批命令从仓库根目录执行 `npm`，因 `package.json` 位于 `web` 子目录而产生 3 个命令路径失败。
5. 将安全断言收窄为检查每条算法路径不存在原始消息字段，并从 `web` 目录重新运行前端验证。
6. 新增组件测试后首次运行发现 Qwen3-4B 同时出现在架构说明和批量评测卡片中，单元素断言失败；将断言修正为验证两个预期展示位置。

## 实验结果

- 后端定向测试：13 passed；Ruff（Python 静态检查）通过。
- 后端全量测试：621 passed，保留 2 条第三方 Starlette（Web 框架底层组件）状态码弃用警告。
- 前端 TypeScript（前端类型系统）类型检查通过。
- 前端组件测试：2 passed，其中新增 1 条 Agent Lab 批量评测展示测试。
- 前端生产构建通过；主 JavaScript（浏览器脚本）产物 200.40 kB，gzip（压缩格式）后 65.58 kB。
- 接口仅包含 120 条隔离测试集的聚合结果，未返回原始消息、逐样本预测或训练数据。
- Qwen3-4B 适配器相对未微调底座的精确通过率提升 7.50 个百分点，但其 13.33% 仍低于规则基线 16.67% 和 DeepSeek 32.50%；页面如实展示，不宣称适配器整体优于其他路径。

## 失败原因或下一步计划

- 本轮两类失败均为测试断言或命令工作目录错误，不是功能回归；修复后验证全部通过。
- 下一步应针对多意图、缺参澄清和安全绕过三类失败做错误分桶，形成“失败类别 → 路由策略 → 数据补强”的调优闭环。
