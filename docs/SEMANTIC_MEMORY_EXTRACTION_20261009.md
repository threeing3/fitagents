# 语义记忆提取与意图调用复用

## 现在的流程
用户消息 → 受控意图路由。

- 需要模型理解：同一次模型请求输出意图和记忆候选，分别解析与校验。
- 未调用意图模型：历史查询和明确确认/取消跳过提取；其他消息在提取工具中调用记忆模型。
- 资料字段提取仍保留现有规则与长资料模型补充，不声称整个回答只调用一次模型。
- 当前消息是事实证据，最多六条近期消息作为指代背景；不从助手回复或历史背景新增事实。

候选 → 原文证据/主体/事实属性/类型/时间范围检查 → 原有记忆校验 → 宿主受控写入 PostgreSQL（关系数据库）。没有新增表或迁移。

## 模型提出什么
候选包括内容、类型、原文证据、用户主体、事实属性、肯定或否定、时间范围和模型置信度。重要度由宿主类型策略产生，模型置信度不是校准后的概率。

原文证据和来源消息编号保存在现有记忆元数据中。候选不放进公开路由投影；执行记录只添加提取状态和候选数量。现有受权限约束的记忆校验记录保持不变。

## 写入与失败边界
- 合法意图不会因记忆字段不合法而被丢弃；合法记忆候选也不依赖意图字段合法。
- 在线记忆提取失败、格式错误、缺少来源或明确禁止保留时，不回退关键词写入事实。
- 离线模式仍有标注为诊断的旧规则路径，供已有离线回放测试使用，不代表模型提取准确率。
- 工具输入不能伪造宿主校验过的候选；重复提取工具调用复用当轮结果。
- 否定疾病事实不生成新的风险记录；旧伤病纠错仍走原有明确纠错链。
- 没有新增允许模型自主删除、替代旧记忆的权限；通用偏好冲突消解不属于此次改造范围。
- 原文证据存在不等于模型理解正确。模型若错误标注主体、假设或否定，仍可能误提，需要持续评测。

## 实际发现的问题
首次真实模型检查把“把明天的跑步换成骑车”提成近期状态，还把“不舒服”理解成负面情绪意义的否定。修复为：增加任务/事实对照示例，明确肯定/否定表示事实是否成立，而非情绪好坏，并在程序端拒绝明确的修改命令片段。

第二轮六条合成消息检查中，偏好、近期睡眠与否定疲劳、膝盖不适被保留；朋友信息、假设和禁止保留的信息为空。只是小样本人工诊断，不是准确率或节省词元的收益实验。

## 验证入口
`tests/test_semantic_memory_extraction.py`：22 项协议、复用、隔离、入库和防伪测试。

`scripts/verify_semantic_memory.py`：六条合成消息真实模型诊断，单独调用模型，不读取或写入业务数据库。

`logs/20261009_semantic_memory_extraction.md`：过程、命令、失败与最终回归结果。

## 面试表达
“我的记忆提取不再依赖关键词直接入库。复杂消息本来需要模型理解，我让这次调用同时给出任务意图和带原文证据的记忆候选，但两部分分别校验。模型负责理解，宿主控制是否写入。我们实际发现过模型把计划修改请求当成长期事实，后来通过对照示例和命令片段校验修复；提取失败不会阻断任务，也不会偷偷用关键词生成事实。”
