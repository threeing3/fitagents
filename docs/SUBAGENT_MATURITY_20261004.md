# 子智能体成熟度验收清单

目标是把FitAgent的领域子任务做成可靠的协作执行机制，而不是宣称已经达到通用开源框架的全部能力。
参考：[DSH官方子智能体规范](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/subagent.zh.md)。
借鉴接口、生命周期、父子关联、能力声明和取消传播，不引入外部框架代码。

## 要完成的能力与证据

| 能力 | 当前状态 | 最终验收证据 |
| --- | --- | --- |
| 独立上下文、受限查询、结构化交付 | 已有；脚本验证 | 实际模型查询循环、攻击和业务案例 |
| 分析→领域建议→规划交接 | 已有；脚本及对话验证 | 固定案例证据准确、约束遵守与完整任务结果 |

| 证据纠正后整体作废 | 已有并修复重复读取漏洞 | 多阶段纠正、前端最新失败状态、禁止旧建议写入 |

## 执行顺序

上表为当前快照。以下分阶段说明保留当时边界，后续更新以对应追加章节为准，不应将历史“尚未实现”视为当前结论。

1. 本轮：固化一次性运行生命周期和严格协议，修复证据覆盖漏洞。
2. 下一阶段：持久化目录与中断事件，再实现宿主可继续子会话和明确控制接口；仍使用现有账户权限和业务存储，修改关键迁移前另行说明。
3. 加入故障恢复、幂等和并发隔离，覆盖真实前端操作与刷新回放。
4. 接入真实受控工作流对照，冻结合成业务集及评分标准，记录真实模型用量和失败归因。
5. 对照这张表逐条重新审计；真实模型结果、端到端和恢复证据不足时不宣称全部成熟。

## 本轮设计取舍

目录绑定当前用户和会话，不使用全局共享字典。工具参数仍由宿主确定，没有开放模型自填用户标识。
单轮内存目录不冒充可恢复子会话；不支持的继续请求在启动前明确拒绝。
取消不伪装成成功结果：模型请求收到取消，剩余子任务不启动，当前目录留下失败原因。
消费者关闭生成器和父任务取消分别记录。当前目录尚未独立落库，所以浏览器中断持久可见性仍需下一阶段完成。
业务查询目前同步执行，时限不能抢占被阻塞的数据库调用；后续需要查询级超时及独立数据库会话，不能靠异步等待伪称所有工具都能被取消。

## 持久化适配器进展

已新增SubagentJournal（子任务目录存储适配器），复用现有执行记录表，验证跨数据库会话读取、用户归属、旧版本冲突、取消状态及事务回滚。
适配器不自行提交事务，当前尚未挂入主对话；因此上表“持久化目录与中断可见性”仍未达到完整验收。
下一步需把生命周期保存接到独立目录事务，避免提交主业务事务，并在PostgreSQL（项目使用的关系数据库）验证并发版本更新。可继续会话与前端中断回放仍待实现。

### 独立事务接入更新

PostgreSQL对话链路现已挂入生命周期保存，每次创建、运行、终态和作废都使用独立数据库会话；锁等待和语句超时只作用于该事务。
专用合成验收库已证明：主事务未提交时目录可独立回读；外层复盘生成器关闭后失败原因保存；主业务探针写入仍可回滚；脚本模型运行中取消会传到模型并保存parent_cancelled（父任务取消原因）。
内存SQLite明确标记未启用独立保存，不冒充事务隔离。
仍缺目录查询的前端接入、进程硬终止后的状态核对、可继续会话及并发恢复；单次脚本取消不是这些能力的证据。

### 会话目录查询更新

新增受认证保护的会话目录接口及对话内默认折叠的“子任务记录”。进入或切换会话、对话忙闲切换和手动刷新时查询持久化目录。
不把目录绑定到未证实关联的回复；错误、无记录、已记录运行态分开显示，晚到的旧会话请求不会混入新会话。
HTTP认证、权限、条数上限与取消状态回读已验证；前端组件验证晚到响应隔离及失败重试。
当前没有自动恢复、可继续会话或存活探测，因此运行态明确标记存活未核对。

### 执行锁与中断核对更新

新运行在整个子任务协作期间持有PostgreSQL会话级锁，目录记录锁协议。核对接口要求当前账户、会话、明确不重跑确认和目录版本；只有取得同一把执行锁才允许将遗留活动态置为中断失败。
无锁协议的旧目录拒绝核对；活跃运行拒绝核对；重复核对不重新执行；版本变化拒绝覆盖。前端提供两步确认且不推断存活。
专用合成数据库已验证自有辅助进程直接退出后释放锁并完成核对，不依赖时间阈值。新增锁会占用一个额外连接，连接池并发压力仍须验收。
这不是可继续子会话：当前只关闭遗留状态，不恢复模型上下文，也不自动重跑模型或工具。

### 可继续子会话内核更新

新增可继续执行内核，明确绑定用户、会话及角色；同一子任务身份最多三次激活，共享九次模型调用，每次重新绑定当前任务的只读查询。
仅已完成的子任务可继续。要求最新子任务版本；失败、关闭、版本过期及越权请求拒绝，不自动重试。
上一轮观测保留在宿主，用于交接前检查；变化时不把旧结果发给模型。交接只含上一轮已验收的结构化建议，不含原始消息历史或观测快照。
专用PostgreSQL合成库已验证两次激活保持同一身份并保存激活编号；模型为脚本，不作为真实模型质量证据。
累计预算和交接目前保存在管理器内存，还没有跨进程载入协议及HTTP/前端续话接入。因此这一能力仍在实现中，不可宣称重启后可继续。

### 跨进程续话更新

已新增私有续话状态保存及加载，包含累计剩余调用、已交付激活、结构化交接和宿主观测，公开目录及执行详情不返回私有状态。
目录完成但交接未确认保存时拒绝恢复；预算在模型请求前保存扣减，不能通过重建管理器增加预算。
专用PostgreSQL合成库验证两个不同Python进程先后运行同一子任务，保持身份且预算从8减至7，累计激活保存为2；模型为脚本。
尚未接入HTTP续话、前端、用户级文本/费用配额以及真实模型协作评测，全部成熟仍未成立。
# 受控业务接口与前端补充（本轮）

启动和续话接口已接到折叠子任务目录；只读建议不能写记忆、批准变更或修改计划。
请求先持久化唯一回执，再运行模型；重复相同请求重放已有结果，旧目录版本拒绝。
断连后前端只查询原请求回执，未确认状态不自动重跑。刷新后待确认请求号恢复已补齐：用户、会话、父任务隔离的会话存储，仅保存请求号；存储失败则发送前阻断。
运行中目录不满足续话资格时仍保留原请求查询入口。最近10条目录之外的旧任务回执发现已补齐，仅提供经过认证的原请求查询，不提供虚假目录或重跑入口。
数据库合成并发检查证明：模型等待期间同请求号拒绝重复执行，不同请求号竞争同一父任务不会增加调用；完成后可重放原结果。不是高并发容量结论。
公开目录仅额外暴露是否可续话，不泄露私有交接内容。
专用 PostgreSQL 合成检查已通过：同身份续话、重复请求不调用、旧版本拒绝、安全拦截、无计划写入。
这些是工程链路证据；真实模型协作收益与公平三组实验仍未完成，不能宣称成熟度已达到参考项目。

## 目前优先剩余项

1. 三组真实业务评测：现有周期聚合规则只读适配器已接入，仍缺完整业务基线、固定业务场景与评分、真实模型用量记录，不能以脚本框架成功替代质量结论。
2. 主动中断控制已接独立子会话及主对话协作树，均提供两步前端确认。主复盘模型等待时独立数据库指令可取消分析并阻断下游，已合成验证；真实供应商与真实数据库浏览器验收仍缺。失败目录的孤儿请求回执核对已实现：执行锁释放、版本匹配、无成功孩子才关闭为失败。成功但交付不明、目录缺失仍不自动关闭，查询不到回执不能凭一次查询擅自认定未执行。目录外核对仍需单目录读取接口。
3. 整树文本/费用配额和多用户连接池压力，不把调用数限制当作费用预算。
4. 真实数据库浏览器链路与完整CI门禁。现有浏览器用受控接口模拟、模型用脚本，证据范围需保留。
