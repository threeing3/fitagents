# 领域状态 + 受控执行 + 长期责任

通用聊天不能保证改的是正确用户的正确记录、未覆盖其他日期、批准前不写入，以及纠正后旧事实不再影响建议。因此长期状态与模型上下文分离。

## 执行主线

当前路由已收敛为“轻量分发 + 领域协作”：规则处理明确请求，复杂请求一次主理解后复用任务集合；默认不运行四层级联，不重复调用模型规划。训练/饮食/恢复只读子任务及证据分析/方案规划复盘保持原能力，执行权限仍归宿主。详细结构及边界见 [轻量分发说明](LIGHTWEIGHT_DELEGATION_20261004.md)。

1. 鉴权并定位账号与会话。
2. 从档案、有效记忆、目标与反馈构造上下文。
3. 明确更正及确认走确定性路径，开放语言任务调用模型提出建议。
4. Harness（智能体执行控制框架）检查工具契约、权限、预算和前置验证，不允许模型直接任意写库。
5. 写操作进入事务；需审批的调整先保存待批准项；重复请求返回既有结果，过期版本拒绝覆盖。
6. 记录事件供页面回放，展示可核验操作，不展示模型隐藏完整推理。

| 状态 | 权威来源 | 一致性措施 |
| --- | --- | --- |
| 用户权限 | 登录身份、记录所属账号 | 每次读写检查归属 |
| 事实记忆 | 档案、训练记录与来源关联 | 更正、旧版本失效、依赖更新 |
| 计划 | 带日期的结构化记录 | 限定变更范围、锁与版本检查 |
| 长期责任 | 责任、审批与后台任务记录 | 暂停、取消、到期、提交前重验 |
| 执行结果 | 工具结果及事件 | 幂等、回放、失败归因 |

## 长期与记忆

责任有用户、时区、期限、状态和审批关系，不是一条永远运行的提示词。后台读取持久化状态，写入前重验；不知道写入是否成功时不盲目重试。本地入口不自动启动后台进程。

记忆区分来源事实、经历和归纳，归纳需要来源支持。训练更正支持时长、主观用力程度及完成状态，不改每组动作明细。明确记录、理由、旧值、版本并确认，事务更新事实；旧记忆与受影响后续判断失效，历史执行证据保留。

## 借鉴与取舍

- [Open Deep Research](https://github.com/langchain-ai/open_deep_research)：参考架构与复现文档，研究报告和健身业务状态不同，不照搬工具链。

不是“最强”排名。当前优先领域约束、可追踪状态及明确的小工具集，不堆多个聊天角色。
