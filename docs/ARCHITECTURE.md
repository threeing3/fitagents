# FitAgent 架构：长期状态、受控执行与领域协作

FitAgent 是面向健身需求的 Personal Agent（个人智能体）。核心取舍是：**模型负责理解与候选建议，宿主负责事实、授权、写入与验收。**

## 一次请求如何执行？

1. 确认登录身份与会话，读写限定当前用户。
2. 明确记录、纠正与确认优先走受控业务路径；其余使用轻量路由，复用同一任务集合。复杂分发至多一次主理解，不代表整个业务只调用一次模型。
3. 组合档案、有效记忆、近期记录、目标与约束，按任务筛选记忆并控制上下文预算。
4. 执行业务链路或受限模型工具循环；需要领域分析时委派只读子任务。
5. 检查工具契约、风险、依赖与修改范围；必要的计划调整先保存候选，批准后重验，使用版本与重复请求保护。
6. 保存公开执行记录，在原有前端查看时间线与历史追踪。

| 路径 | 模型职责 | 宿主职责 |
| --- | --- | --- |
| 受控业务链路 | 理解、抽取、候选计划与回复 | 确定步骤、验证依赖、执行业务写入 |
| 模型工具循环 | 从允许工具中选择动作，根据结果继续或回答 | 暴露只读能力、校验请求、限制轮数与预算 |
| 领域子任务 | 独立上下文读取证据，提交结构化建议 | 投影证据、限制工具、跟踪生命周期、验收交付 |
| 周期复盘 | 分阶段分析、领域建议与候选规划 | 共享预算、交接重验、失败阻断，保持审批边界 |

模型工具循环不是覆盖所有业务的通用入口。写操作不因模型生成工具请求就获得授权。

## 记忆：召回与有效性是两件事

区分事实、经验、观察与归纳，保存来源。任务化召回先选择类型：计划与风险任务优先事实及有结果依据的经验，避免无依据归纳占据事实位置。

向量、关键词、实体与时间多路取候选；结合 BM25（关键词相关性评分）、RRF（多路排序融合）、重要性、时间与适用性综合排序。这里是候选融合与规则评分，不是经过训练的记忆重排模型。

默认检索限定账号、有效状态与有效时间。用户纠正后，旧事实退出默认召回，派生记忆沿来源依赖级联失效。**来源曾经可靠，不代表它现在仍有效。** 保留历史证据，不把失效当物理删除。

源码：[记忆系统](../fast_api/app/services/memory_system.py)、[召回规划](../fast_api/app/services/memory_planner.py)、[依赖失效](../fast_api/app/services/memory_dependencies.py)、[上下文构建](../fast_api/app/services/context_builder.py)。

## 子智能体：有证据的建议，不是独立写入权限

领域角色为训练、饮食与恢复。周期复盘按以下顺序交接：

**证据分析 → 训练 / 饮食 / 恢复建议 → 方案规划 → 宿主验收**

子任务按账号与职责投影上下文，不接收任意数据库访问或写权限；只读记忆、记录与约束，提交摘要、建议、不确定项及证据编号。建议不是事实、审批或已执行结果。

复盘共享预算，阶段交接重新读取证据，最后交付再次核验。证据变化、刷新失败或前置任务失败时阻断后续链路，不能把旧建议用于新状态。生命周期、父子关系与终止状态进入持久目录及公开事件，支持受控继续和中断查看。

这能说明协作与权限设计，但不证明多智能体效果或成本优于单智能体。范围见[成熟度清单](SUBAGENT_MATURITY_20261004.md)。

源码：[领域子任务](../fast_api/app/services/domain_subagents.py)、[复盘协作](../fast_api/app/services/review_collaboration.py)、[运行内核](../fast_api/app/services/subagent_runtime.py)、[持久目录](../fast_api/app/services/subagent_journal.py)。

## 长期责任与业务状态

责任保存账号、时区、目标、期限、状态及审批关系，不是一条永远运行的提示词。后台工作进程需单独启动，写入前重验状态。结果未知时先核对提交凭据，不盲目重跑。

| 状态 | 权威来源 | 保护措施 |
| --- | --- | --- |
| 用户权限 | 登录身份与记录归属 | 每次查询与操作检查账号范围 |
| 事实记忆 | 档案、记录与来源 | 旧版本失效、派生依赖更新 |
| 计划 | 日期、约束与版本 | 修改范围、审批、冲突与重复执行检查 |
| 长期责任 | 责任、审批与任务记录 | 暂停、取消、到期、提交前重验 |
| 执行结果 | 业务状态、提交凭据及运行记录 | 业务提交与日志完成分别核对 |

PostgreSQL（关系数据库）保存持久业务状态；Redis（缓存服务）不替代授权与业务状态检查。基础设施不是此项目的主要展示主线。

## 追踪不等于隐藏推理，也不等于重新执行

实时事件与历史投影展示已保存的公开过程：路由、工具、验证、审批和子任务交接。历史读取不重新批准或执行业务。中断保留持久前缀，无终止记录标为未确认，不能凭日志猜业务提交是否成功。

记录可能包含摘要、截断内容与源内顺序，不承诺精确复现每次模型请求、全局事件顺序或全部中断前事件。只供本人查看，公开素材使用合成数据。见[追踪指南](EXECUTION_TRACE_GUIDE_20261004.md)。
