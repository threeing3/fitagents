# FitAgent 意图与动作决策策略（2026-09-24，执行前方案）

## 一句话目标

把用户一句话里的多个任务、风险和更正，转成可执行且可核验的结构化决策。主意图准确率不是最终目标；更重要的是该做的动作不遗漏、不该做的动作不执行、纠正后不沿用旧事实，以及在不确定时正确澄清。

本方案只使用自构造和已有合成数据。它不是在线系统效果、真实用户数据或医疗/运动安全认证。Jev 是候选决策器，不因其输出类型受限就推定语义正确。GPU 训练要等协议冻结及预检后再决定。

## 1. 现有系统和真实瓶颈

- 线上代码已有规则初判、意图适配器、低置信字段交给 DeepSeek 复核、风险规则下限、澄清协议、`IntentDecisionV2` 结构契约和工具规划。不能把它描述成“从零搭建意图路由”。
- 旧 Qwen3-4B QLoRA 已训练过，但历史独立挑战集安全合并后的完全匹配仅 13.33%；不能凭格式合法率 100% 宣称模型可接管决策。
- v3.1 数据共 956 条，720 训练、236 验证；其中 188 条教师候选仅自动筛选，人工语义审核为 0。90 条独立开发集为人工编写模板，亦未审核。数据不是用户真实消息。
- v3.1 字符 TF-IDF 基线在 90 条开发集上主意图准确率 0.4889，次意图 Macro-F1 0.3194、集合完全匹配 0.5000；`monthly_review`、`profile_correction`、`recovery_check` 的 F1 仍为 0。模板近重复和标签稀疏比 GPU 不足更可能先限制泛化，但这是待检验解释，不是确定因果。
- 现有字段路由以 `primary_intent=0.80`、`secondary_intents=0.75` 为默认阈值，开发协议报告明确没有用实时适配器验证。阈值不能当作已校准概率。
- 规则风险词表含疑似编码损坏文本；风险检测须单独审计。否定、引用、历史已解决伤痛和当前危险征象，不能仅靠子串命中区分。

## 2. 决策对象：先拆语义，再定优先级与动作

每轮输入包含当前消息、会话中已确认的用户状态及可用工具。输出继续遵循 `IntentDecisionV2`，但解释为以下五层：

1. **语义事实层**：独立识别用户在本轮是提出请求、报告已完成事实、纠正旧事实、询问旧信息，还是引用/否定/假设。为每个片段保留文本证据、时间（过去/现在/计划）、极性（肯定/否定）、对象和槽位；不凭模型生成值直接写数据库。
2. **任务层**：多标签提取所请求的任务，例如记录训练、修改画像、生成计划、恢复评估。允许零个、一个或多个任务，明确“不要生成计划”是禁止动作，不是计划请求。
3. **安全层**：把症状、疼痛和高危征象交给确定性风险下限与澄清协议。模型可提示新增风险，但不得把规则检出的风险降级。过时或被纠正的风险事实不应再作为当前禁令。
4. **政策层**：根据优先级、用户授权、必要槽位和安全状态形成 `requested_actions`、`allowed_actions`、`blocked_actions`、`candidate_tools`。分类器只能提出候选；工具执行许可由政策与业务状态决定。
5. **审计层**：同时保留原始模型判断、规则判断、融合后的最终决定、置信来源与各字段耗时。最终状态和工具轨迹必须可回放核验。

主意图仅用于显示和旧接口兼容，按既有优先级从已识别任务中选；次意图是其他已请求任务。不要让主意图单标签选择抹掉第二个任务。若只有风险描述、无明确训练请求，则不能自动创建训练计划。

### 决策示例

用户说：“昨天卧推三组帮我记一下；肩膀今天抬起会刺痛，先别安排推举。”预期是 `training_log` 请求与当前风险并存；记录动作可在必要槽位齐备时执行，推举计划被禁止；若训练记录缺重量但业务允许部分记录，应按业务契约处理，不能凭空补重量。主意图按安全优先级可为 `injury_or_risk`，但不得漏掉训练记录。下一轮“我说错了，痛的是上周，今天不痛；昨晚是两组”则应形成纠正事件：旧伤痛当前性和旧组三事实失效；是否恢复计划许可仍须遵守必要的安全澄清，不可仅凭分类概率自动放行。

## 3. Jev 的位置与对照

Jev（TypeSafe AI 的有界类型化决策模型）公开能力是对有限选项、布尔值或分数作判断；它适合与当前生成式解析器对照，承担**语义候选字段**，不负责代码规则、数据库写入、风险下限或工具副作用。官方资料：[TypeSafe AI 介绍](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[API 文档](https://api.typesafe.ai/docs)、[Vercel 使用边界](https://vercel.com/i/when-to-use-jev)。公开速度、价格和基准结果属供应商陈述，不能转写为 FitAgent 的实测收益。

在同一条输入上比较四条候选路径：

| 路径 | 作用 | 主要可检验假设 |
| --- | --- | --- |
| 规则 + 既有澄清协议 | 零模型成本基线 | 复杂多意图、否定和改口是否失败 |
| 字符 TF-IDF + 独立多标签头 | 可复现轻量基线 | 小数据下能否稳定覆盖常见表达 |
| Jev 有界决策 | 不训练的类型化语义候选 | 能否降低解析失败、改善字段判断及延迟/成本 |
| 已有 Qwen3-4B 适配器及候选 v3.1 新训练 | 可训练模型路线 | 经审核的数据是否改善未见表达和多意图 |

每条路线都输入相同的匿名化上下文和允许标签，输出先映射到同一字段契约。Jev 的多标签不能用“一次选一个主意图”代替：可按任务族分别做布尔判断，再用确定性优先级选主意图；需要验证独立判断的互相矛盾与调用成本。若 Jev 只返回类型合法、不理解否定或更正，它不应被采用。无可用密钥或单价未确认时，Jev 路线标为“未运行”，不得用供应商报告填实验表。

建议最终采用“确定性安全/政策 + 最合适的语义候选 + 置信不足时澄清或复核”，而不是预设 Jev 或 QLoRA 必须胜出。现有 DeepSeek 字段复核保留为被测基线，不把多模型相互同意等同于真值。

## 4. 数据与标注协议

### 数据来源及标签

保留 956 条 v3.1 作为**既有合成训练候选**，不直接当高质量金标。188 条教师候选逐条审核文本自然性、全部意图、否定/时态/对象、风险是否低标、任务槽位和可执行性；记录审核者、时间、结论、修改前后及理由。未审核或有争议样本不进入下一次正式训练。已有 90 条开发集只做错误诊断，不用于生成新训练文本、拟合阈值或挑选展示案例。

另起自构造、按场景编写的挑战集，优先覆盖以下成对最小差异，而不是堆同一模板的改写：

- “练了”与“想练”、已记录与请求记录；同一消息含记录 + 计划 + 风险。
- “肩痛”与“上周肩痛已消失”、引用别人肩痛、否定“并不痛”；当前红旗与历史红旗。
- “不要修改计划”与“修改计划”；“把三组改成两组”的旧值定位、同名多条记录。
- 记忆问询与记忆纠正；资料更新与资料纠正；缺槽位、冲突槽位和用户撤回。
- 多轮先前意图被新消息覆盖；旧记忆失效后检索；工具响应丢失与重复请求。

每条案例保留 `case_id`、场景族、来源、原文、允许的上下文、原子请求标签、主次意图、风险证据、必要/禁止动作、期望澄清、预期最终状态和审阅状态。长文本按子句标证据，给“无请求”和“不可判定”合法标签。安全关键案例至少双人复核或明确仲裁；若暂时只有本人审核，诚实记录单人审核和不确定项，不宣称专家金标。数据不得包含真实患者或用户信息。

按场景族、生成来源、改写母句、会话链整体隔离训练/校准/开发/最终测试；近重复检测只是辅助，不替代语义隔离。阈值仅在校准集选择；开发集用于一次性设计诊断，固定测试仅在方案冻结后运行一次。已有 120 条挑战集若被用于过去调试，只能叫回归集，不再当新盲测。

## 5. 指标与验收门槛

优先按**任务和事件**计量，分类指标是诊断项。

| 层级 | 必报内容 | 失败时归因 |
| --- | --- | --- |
| 语义 | 主意图准确率；次意图逐类 Precision/Recall/F1、Macro-F1、集合完全匹配；否定/时态/更正切片 | 标签、数据、模型或阈值 |
| 安全/政策 | 当前高风险漏检数、禁止动作误放行数、非风险误阻断数、必要澄清召回、无效澄清率 | 风险规则与语义融合分开报 |
| 结构/路由 | 类型合法率、解析失败、回退率、字段来源、校准误差、覆盖-风险曲线 | 避免用格式合法掩盖语义错误 |
| 任务/状态 | 最终数据库正确率、遗漏任务、重复写入、纠正后旧事实误用、工具轨迹正确率 | 只读回放与隔离数据库核验 |
| 资源 | 端到端 p50/p95 延迟、每任务模型调用数与费用、GPU 训练总费 | 同硬件/服务条件对照 |

拟定发布门槛：结构非法或执行禁令违规在固定安全集上必须为 0；高风险漏检不劣于规则基线；任务完成率与纠正一致性优于当前系统，且不能以明显更多误阻断换取。由于安全集规模有限，0 例不是总体零风险证明；汇报每类样本数、置信区间和全部失败例，不仅给百分比。若任一高危误放行，停止自动执行路线，回到规则/澄清，不用调低评价标准绕过。具体阈值须在校准集按风险-覆盖曲线冻结，不沿用未经验证的 0.80/0.75。

## 6. 执行顺序与决策门

1. **协议冻结前**：核对 `IntentDecisionV2` 字段语义、真实业务工具权限、标签边界与 90 条开发集争议；记录混淆样例。此步不需要 GPU。
2. **数据审阅**：完成候选审核与新挑战集的独立编写/复核，冻结训练、校准、开发、最终测试清单及任务级期望状态。审核不完成，不启动“提升模型质量”的全量训练。
3. **低成本对照**：在相同输入和切分下跑规则、TF-IDF、现有适配器；若具备密钥且估算费用明确，再加入 Jev。先完成少量接口烟雾检查与响应映射，再做全量；Jev API 调用需单独预算确认。
4. **GPU 候选实验**：只有当现有适配器在未见表达上确有可训练的错误、数据质量达标且 50 条烟雾预算可控时，才恢复 Qwen3-4B QLoRA。先烟雾训练、全新进程重载、运行记录完整性；通过后新建不可变快照和全量运行。总 AutoDL 实验费用不超过用户授权的 100 元；实例身份、实时 GPU、小时价与余额须重新确认。
5. **策略选择**：按安全门槛、任务成功、延迟/费用选单一路线或字段级混合。判别模型、Jev 或适配器的输出只能经政策层授权，不能直接调用写入工具。
6. **业务回放**：在隔离构造数据上接通分类—状态—工具—记忆纠正链路，逐例保存前态、决策、调用序列、后态和失败原因。通过后再考虑演示，不推断线上收益。

本文件是执行前策略，不是既有实验效果。旧 `smoke-v3-1-seed42-v2` 快照和计划保留为历史准备记录；若数据、标签或训练配置改变，必须新建计划修订和快照，不直接复用旧编号。AutoDL 2026-09-24 页面在数次只读读取中列表条数从 14 变为 7、再变为 5；用户随后说明正在释放旧实例，这是列表变化的已知原因。复核时剩余 5 条列表里没有 RTX 4090，旧计划中从 841 机克隆的步骤不再可执行，后续必须重新制定资源方案；本次没有开机、克隆、上传或训练。

## 7. 首轮执行后的收敛（2026-09-24）

已建立 12 条、6 对自构造开发探针，覆盖当前/不存在的症状、本人/他人的高危征象、明确请求/禁止计划、画像更新/纠正、查询/新增记录及周/月复盘。案例未经过独立人工审核，不能作为最终测试或训练数据。逐例结果保存在 `algorithm/evaluation/reports/intent_semantic_probe_v1_*_20260924/`。

首轮规则路径 6/12 全字段通过；修复“本周”被误当周复盘后为 7/12。旧 90 条开发集曾短暂出现主意图回归：明确“总结最近七天”的周复盘漏识别；补充这一范围表达后，主意图准确率恢复到原有 0.3333。旧集全字段率从原报告的规则 0、规则加协议 0.0667，变为 0.0333 和 0.1000；这是未审阅开发模板上的诊断，不是线上收益。实际改善仅证明时间范围与复盘动作需要同时出现，不能证明通用语义理解能力。

在同一 12 条探针上，v3.1 的 TF-IDF 使用 720 条合成训练样本、236 条隔离验证样本拟合次意图阈值，意图必要/禁止检查通过 5/12；修复后的规则为 7/12。两条路径的风险、工具权限输出范围不同，因此只比较意图检查，不混比全字段率。样本量和标签审核不足，不得据此宣布某一路线整体胜出或放弃训练。

当前仍失败：风险场景中的计划改写表达漏识别；朋友的症状被当成本人风险；历史记录查询被判成新训练记录，另一个记录加查询请求又漏掉查询。这些分别涉及请求语义、症状归属和查询/写入区分。尤其后两类会影响工具副作用，下一步优先扩充对照与检查业务状态，不依靠一条模板直接改安全放行规则。

代码契约还有待核对：`_choose_primary` 与 `TASK_PRIORITY` 的优先级不同；`IntentDecisionV2.from_legacy` 把任务计划中的阻断步骤也收进 `requested_actions`；`candidate_tools` 目前由全部主次意图生成，尚需与最终执行许可逐层比对；`_risk_evidence` 是原文词面命中，可能包含否定或第三人称提及。以上是静态检查发现的潜在语义问题，不能未经执行轨迹验证就称为实际越权或错误写入。
