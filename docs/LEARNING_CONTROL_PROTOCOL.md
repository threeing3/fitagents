# 学习总控协议：通过 Codex 对话掌握算法

## 目标

这个项目不是让你背命令，而是让你在一个真实业务系统里形成完整的算法能力：

```text
概念理解 → 实验预测 → Codex 执行 → 结果解释 → 代码变体 → 错误分析 → 面试表达
```

当前对话承担总控职责，负责维护课程顺序、学习进度、实验日志、未解决问题和下一项任务。你可以只通过自然语言学习；命令由 Codex 在项目环境中执行并解释。

## 双方职责

### 你的职责

每次学习只需要完成四类输入：

1. **概念回答**：用自己的话解释当前概念，不要求一次准确。
2. **实验预测**：在看到结果前，预测指标、失败案例或权衡，并说明理由。
3. **代码决策**：在多个实现方案中选择一个，说明为什么。
4. **复盘表达**：用 30–60 秒回答“业务问题、算法方案、指标、失败和限制”。

你不需要自行复制终端命令，也不需要独立维护进度文件。

### Codex 的职责

我会在每轮：

1. 说明本轮学习目标和前置知识。
2. 先提一个小问题，让你做预测，再执行相关代码或测试。
3. 展示关键输入、输出、指标和错误样例，而不是只报告“通过”。
4. 把实验动机、改动、命令、步骤、结果、失败原因和下一步写入可读日志。
5. 给出一个范围受控的代码任务，必要时直接实现并让你解释取舍。
6. 更新 `learning_progress.json` 中的模块状态和证据；没有解释和错误分析时不会标记为掌握。

## 一轮学习的固定节奏

### 1. 定位

我会告诉你当前模块、它解决的业务问题、会阅读的最小文件集合，以及本轮验收标准。

### 2. 预测

你先回答一个问题，例如：

> 如果把按行随机切分改成按用户切分，验证集指标通常会怎样变化？为什么这会让结果更可信？

预测不需要正确；它的作用是让你在结果出现前建立可检验的假设。

### 3. 实验

我会执行测试、基线脚本或小规模消融实验。长实验必须使用独立 `experiment_id`，并写入 `logs/experiments/`，不覆盖历史记录。

### 4. 讲解

我会把实现映射到算法概念：输入如何变成特征，标签怎样定义，指标回答什么问题，规则和模型的边界在哪里。

### 5. 变体任务

每个模块至少完成一个变体：新增边界样例、替换特征、改变切分策略、增加对照模型或修改排序规则。变体要有假设，不能只改代码看是否通过。

### 6. 错误分析

我们至少保留一个失败样例，并判断原因属于数据、特征、模型、规则、评测还是系统集成。安全问题优先由确定性护栏兜底，不能用模型平均分掩盖。

### 7. 验收与迁移

满足“概念能解释、实验能复现、代码能修改、错误能定位、面试能表达”五项后，才把模块标记为 `mastered`（已掌握）。否则保持 `in_progress`（进行中），记录疑问并进入下一轮。

## 模块切换规则

- 默认按 `01 → 02 → 03 → 04 → 05 → 06 → 07 → 08` 推进。
- 当前阶段优先完成数据契约、数据治理和应用算法基线，再启用 GPU 后训练。
- 如果某个模块出现基础概念缺口，我会暂时回退到前置模块做一个最小补课，不重置已经完成的证据。
- 新对话可以专门讨论单个模块；总控对话仍负责决定是否通过和安排下一模块。

## 掌握门槛

一个模块不能仅凭测试通过而算完成。至少要留下：

- 一次自己的实验预测；
- 一次代码或数据变体；
- 一条失败样例及原因；
- 一份实验日志；
- 一段面试式总结。

## 对话中的快捷指令

你可以直接说：

- “开始下一个模块”：我读取进度并提出本轮问题。
- “先讲概念”：我暂停代码修改，用例子和反例解释。
- “执行实验”：我运行当前模块的最小可复现实验。
- “检查我的理解”：我用追问和反例测试，而不是直接给答案。
- “记录本轮”：我把结论、疑问和证据写入进度与日志。
- “准备面试回答”：我把本模块整理成 60 秒、3 分钟两个版本。

## 真实数据与模拟数据边界

项目可以使用规则生成、教师模型生成、合成数据和模拟业务结果补足样本，但每条数据必须保留 `source`（来源）字段。模拟环境的接受率、依从性或恢复改善只能用于方法验证，不能表述为真实线上收益。
