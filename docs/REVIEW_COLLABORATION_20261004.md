# 证据驱动周期复盘协作

## 现有业务接入

周/月复盘进入以下链路：

主智能体 → 证据分析 → 训练／饮食／恢复建议 → 方案规划 → 主智能体整理回复。

普通领域咨询仍按需运行领域子任务；记录写入、记忆纠正、审批、医疗安全回应保持在宿主，不绑定为一种意图一个子智能体。
危险症状任务不进入这条协作链。三个领域当前顺序执行，而不是并发共享数据库会话。

## 子任务和交接

- 证据分析：读取当前有效记忆、业务记录、约束与现有计划；输出有依据的摘要、缺失信息与不确定性。
- 领域建议：拿到分析的结构化交付及自己的领域上下文，不拿完整历史；只提供建议。
- 方案规划：接收分析和三个领域结果，结合当前计划、日期、运动限制、风险和用户授权范围提出候选调整或澄清。
- 宿主：验证返回格式和引用来源、复读依赖、控制调用与时限；处理失败、取消和权限。建议本身不会写入计划。

统一交付字段：summary（可公开结论摘要）、recommendations（候选建议）、uncertainties（不确定性）、evidence_ids（实际提供的记忆或记录引用）。
这不是模型隐藏思考。来源存在检查不证明结论与来源在语义上相符，仍需要正式评测。

## 真正遇到的工程问题

1. **规划成功不代表整条链还有效。** 用户可能在领域分析期间把40分钟改为20分钟。规划自己的查询没变化，分析结论仍可能过期。
   因此保存各子任务的只读观测，在交接及最终交付复读；变化后删除内存中的旧建议字段，事件状态改为失败。没有删除用户文件或记录。
2. **检索排序不是事实版本。** 排序分数会随时间变化；比较记忆内容与生命周期，去掉瞬时排名字段，避免无意义的重做。
3. **离线不是完成。** 无模型时五个角色显式跳过，回复说明未完成复盘；不会给固定模板冒充联合分析。
4. **同样的调用次数不等于公平算力。** 单智能体可以用满15轮，而不是只有3轮；协作组共享15轮。正式比较还要量化输入输出token（模型处理的文本单位）和实际费用。
5. **前端不能停留在旧的成功状态。** 子任务按身份折叠最新事件，证据作废后保留失败提示，并可展开查看此前审计过程。

## 对照执行器

`algorithm/evaluation/review_collaboration_eval.py`接收同一case_id（场景标识）、任务和上下文，运行三个方案：

| 方案 | 任务组织 | 调用上限 |
| --- | --- | --- |
| 受控工作流 | 外部传入真实现有工作流适配器 | 15 |
| 单智能体 | 一个角色完成分析和候选规划，可自己循环查询 | 15 |
| 多智能体 | 分析、领域建议、规划，显式交接 | 全部共享15 |

默认工作流适配器现已复用生产ReflectionService的周期统计、保守意见和恢复信号计算函数，输入同一冻结场景，不写记忆或计划。真实上下文的四类业务记录已补编号，以便引用追溯。
它是现有聚合规则的只读快照适配，不是完整生产工作流：不包括数据库检索、责任调度、运动组明细和宿主最终模型回复。共享工具不提供运动组明细，因此明确显示未知，不把空输入当作零运动组。
尚未运行真实模型对照，不存在“三组业务收益已验证”的结论。工作流规则基线调用0次模型，两个智能体组上限15次；上限相同不代表实际费用或文本预算匹配。
执行器保留组级失败和超时，保证关闭子任务生成器；模型等待中取消的调用仍计入消耗。工作流异常后用量未知则记null（未知值），不能伪造为0。外部取消仍向外传播。
正式评测需要固定场景集、相同模型、工具与输入、调用/文本/费用预算，并逐项评审任务完成、证据准确、约束遵守、越权、成本、耗时。
建议覆盖：完整记录、缺失饮食记录、睡眠不足与加量冲突、禁止跑步、日期调整、用户纠正旧记忆、工具故障、子任务超时、取消。

## 权限和当前完成边界

两个独立角色、领域交接、证据依赖作废、对话接入、持久化执行事件和三组运行入口已经实现。
规划输出是建议草案，不是可任意执行的结构化日程。既有指定日期减组申请仍由宿主校验责任授权、计划归属、基线和日期，再等待用户批准；本阶段没有让子智能体自动调用该写接口。
因此目前可以讲协作机制及已验证的失败处理，不能讲真实模型协作增益、正式三组评测结论或自动调整上线效果。
