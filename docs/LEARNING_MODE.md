# 学习模式：把项目变成你的算法训练场

这个项目现在有两种使用方式：

1. **展示模式**：运行基线、展示数据流、比较模型指标。
2. **学习模式**：按课程卡阅读代码、做练习、跑验收、记录证据，直到可以独立解释算法取舍。

学习模式不是把答案直接喂给你，而是要求每个模块完成“概念 → 改代码 → 做实验 → 分析错误 → 面试表达”五步闭环。

## 快速开始

```powershell
# 查看 8 个学习模块
python -m algorithm.learning.mode list

# 查看当前应该学习的模块
python -m algorithm.learning.mode next

# 查看某个模块的目标、代码、练习和面试题
python -m algorithm.learning.mode show 03_intent_and_routing

# 开始一个模块
python -m algorithm.learning.mode start 03_intent_and_routing

# 执行模块验收
python -m algorithm.learning.mode check 03_intent_and_routing

# 验收通过后记录证据，状态变为 mastered
python -m algorithm.learning.mode master 03_intent_and_routing --evidence "新增 5 条风险样例，Recall 和混淆矩阵分析见实验日志" --note "继续补充边界样例"

# 查看总体进度
python -m algorithm.learning.mode progress
```

第一次使用时，`init` 会创建 `algorithm/research_state/learning_progress.json`；它不会覆盖已有进度。

## 8 个模块与能力地图

| 模块 | 你要掌握的能力 | 对应面试方向 |
|---|---|---|
| 01 数据契约 | Python、Schema、JSONL、版本化接口 | 数据工程与训练样本设计 |
| 02 数据治理 | 脱敏、去重、用户切分、泄漏识别 | 数据质量与实验可信度 |
| 03 意图路由 | 分类指标、混淆矩阵、风险 Recall | 应用算法基线 |
| 04 记忆召回 | BM25、向量、混合召回、Recall@K | 检索与排序 |
| 05 工具规划 | 结构化预测、工具顺序、安全硬门 | Agent 应用算法 |
| 06 业务建模 | 标签、特征、AUROC、校准、NDCG | 业务算法 |
| 07 SFT/DPO | QLoRA、偏好对、Adapter、安全回归 | 后训练 |
| 08 评测表达 | 消融、错误分析、复现、模型卡 | 综合面试表达 |

## 每个模块的学习协议

### 1. 先写假设

在执行命令前，用一句话写下你的预测，例如：“加入风险关键词特征后，injury_or_risk 的 Recall 会提升，但普通训练计划的 Precision 可能下降。”

### 2. 再读最小代码面

只读课程卡列出的文件，先回答“输入是什么、输出是什么、指标是什么、失败会怎样”，再运行代码。

### 3. 必须做一个变体

不能只运行现有 baseline。每个模块至少改一个参数、增加一条样例、替换一个排序规则或加入一个对照模型。

### 4. 记录实验，而不是只看分数

实验日志至少包含：动机、假设、修改、命令、结果、错误案例、结论和下一步。不要把模拟数据结果描述成线上真实收益。

### 5. 通过面试自测

课程卡中的问题要能脱稿回答。推荐使用以下句式：

> 在什么业务问题下，我选择了什么 baseline；指标为什么这样定义；实验中发现了什么失败案例；我如何通过数据/模型/规则修复；还剩什么限制。

## 4–6 周学习节奏

- 第 1 周：完成 01–02，能独立导出、校验、切分训练数据。
- 第 2 周：完成 03–05，能解释意图、检索、工具规划三条应用算法链路。
- 第 3 周：完成 06，建立业务结果标签和 CPU 可解释模型。
- 第 4 周：完成 08 的评测协议，并整理错误分析和面试叙事。
- 第 5–6 周：完成 07，在 AutoDL 运行真实 QLoRA；有足够偏好对后再运行 DPO。

## “掌握”而不是“完成”的判断

一个模块只有同时满足以下条件才标记为 `mastered`：

- 能不看答案解释核心概念和关键取舍。
- 能修改代码并提出可验证假设。
- 能运行验收并解释指标变化。
- 能指出至少一个失败案例和一个数据/安全风险。
- 能用 60 秒讲出该模块对业务的价值。

如果只是跑通命令但无法解释结果，应保持 `in_progress`，在 `note` 中记录疑问。
