# FitAgent 意图识别前瞻诊断题 v1（2026-09-28）

## 要回答的问题

旧版 Qwen3-4B 在已经用于开发的 120 题上全字段通过 16/120，但旧提示未列合法标签，历史分数不足以判断模型容量是否是主因。本题集用于下一轮**配对诊断**：固定输入、标签目录、提示与解码条件后，看 4B 与更大模型在语义区分上是否出现可重复的差异。它不验证上线安全性，也不替代多轮业务状态回放。

题目保存在 `algorithm/datasets/fixtures/intent_prospective_diagnostic_v1.json`。共 32 条，8 个场景族各 4 条；每条只有当前一句用户消息，模型输入不得附带预期标签、解释或题目类别。题目全部由助手依据公开的项目意图目录和已有错误类型自构造，没有真实用户或患者信息。

## 独立性与审阅边界

- 旧 `tests/evals/agent_challenge_cases.json` 的 120 条和 `intent_semantic_probe_v1/v2/v3.json` 是已使用的开发/回归材料，不计入这 32 条的新测分数。新题虽经机械精确去重，但场景方向受旧错误启发，**不是完全盲测**。
- 32 条的 `training_eligible=false`；不用于训练、阈值选择、提示词逐题修改或挑选展示案例。见到任何模型输出后，v1 原题和原标注保留；修订须另起 v2 并说明原因，不覆盖 v1 分数。
- 初稿由助手起草；第二位 AI 子 agent 只看题面做了 32 条盲标，四字段全一致 30/32，009/012 的澄清字段不一致。对照和理由见 `algorithm/datasets/reviews/intent_prospective_diagnostic_v1_blind_review.md` 与独立保存的 `algorithm/datasets/reviews/intent_prospective_diagnostic_v1_adjudication.md`。仲裁保留原标注的 `true`：当前高风险要立即给安全提示，后续仍需追问；澄清不阻断安全提示。**这不是人工双审或医学专家金标**。若将来有真人复核，应在看模型输出前完成；未仲裁题不得进入主要比较分母。
- 本题集测试的是单轮语义候选。用户纠正后的记忆失效、实际数据库写入、工具重试等另用既有隔离业务回放检查，不因意图标签正确就宣称任务成功。

## 标注约定

每题固定 `case_id`、`family`、`user_message`、`expected_primary_intent`、完整 `expected_secondary_intents`、`expected_risk_level`、`expected_clarification` 及仅供审阅的 `rationale`。主意图在多个肯定请求中按现有 `IntentRouter.TASK_PRIORITY` 选；次意图是剩余的全部肯定任务，不能把显式禁止动作算作次意图，也不能额外输出无请求任务。`general_chat` 表示没有可执行任务的陈述/拒绝。

本题的风险标注只针对**用户本人当前**状况：本人当前呼吸异常或胸口发紧标 `high`，需要后续澄清但应先给安全提示；明确是第三人、引用或被本人否定时标 `low`。这只是用于比较分类器的产品内诊断约定，不是医疗分诊标准。风险字段使用精确等级评分，不采用“达到最低等级即通过”的旧宽松口径。澄清字段只在用户明确要求先问、任务所需值缺失、或当前高风险需要补问时标 `true`；它不等于“禁止立即安全回应”。缺槽位不得由模型臆造。

题组分别覆盖：记录/查询边界、计划请求的否定、风险归属、画像更正/更新、多任务保留、必要澄清、周期复盘/单条查询、口语干扰。每个场景族必须连同全部失败例一起报告，不能只摘通过案例。

## 下一轮执行约定（本轮不跑模型）

1. 在看任何新模型输出前，完成独立语义复核；冻结统一提示词，明确列出 16 个合法意图、四档风险值、布尔澄清字段，并使各模型接收完全相同的 `user_message`。当前旧推理提示只有字段名，没有合法标签说明，不能直接用作公平基础模型对照。
2. 先对同一 32 题做无训练的推理对照：旧 4B 基础模型、已有 4B 适配器和候选较大模型。分开记录原始输出与确定性安全合并后的输出；每条保留模型版本、提示版本、解码参数、结果和耗时。未能加载的路线明确标“未运行”，不沿用旧预测填表。
3. 逐题报告解析成功、合法标签、主意图、**次意图精确集合**、精确风险等级、澄清、全字段精确通过；另报高风险漏检、非风险误报及各场景族的分子/分母。32 条只够定位失败形态，不足以估计广泛用户分布或证明总体安全。
4. 比较以同一题为配对单位，展示 4B 错而大模型对、大模型错而 4B 对的案例清单及调用耗时。若改进集中在格式/标签合法性，而语义对照无改善，先修提示/契约；若两者都在相同语义边界失败，优先复核标签与数据；只有在固定协议下大模型稳定修复了语义错误，才考虑扩大参数量或付费训练。

现有 `intent_local_model_eval.py` 的 `schema_valid_rate` 只计字段结构，`intent_checks` 对次意图使用子集匹配、对风险使用下限匹配；**不能直接拿它们的旧“全字段通过”当本题的精确评分**。本轮另建严格计分并完成单元测试；真实模型预测接入时还需核对逐题原始输出。旧历史报告不覆盖。

严格评分器已放在 `algorithm/evaluation/intent_prospective_score.py`。输入预测为逐行 JSON，每行至少有 `case_id` 和模型原始 `text`；顺序可变，但 ID 必须与题集一一对应，缺失、额外或重复 ID 都拒绝计分。它分别统计可解析、合法目录、主意图、完整次意图集合、精确风险、澄清、全字段，以及高风险漏检和非高风险误报。调用方式（把输入/输出文件名换成实际运行记录；当前还没有模型预测文件）：

```powershell
.venv\Scripts\python.exe -m algorithm.evaluation.intent_prospective_score --dataset algorithm/datasets/fixtures/intent_prospective_diagnostic_v1.json --predictions <本轮逐行预测.jsonl> --report-output <本轮严格评分.json>
```

## 停止条件

独立复核发现无法按现有 16 类意图一致标注、题目与训练/旧题存在实质近重复、模型使用了不同输入/提示、或新评分器无法逐例复核时，停止规模比较并修订协议；不以临时删题、看结果后改标或换门槛救分。本轮无 AutoDL 开机、训练、下载权重和付费调用。
