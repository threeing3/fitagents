# 业务流程验收

当前验证方式以实际业务流程为主，不再运行已删除的单元与页面自动测试套件。
代码规范、格式、类型、安全、接口描述与构建检查继续保留。

## 每轮操作原则

- 使用专用验收账号和隔离数据库，不使用真实患者数据，不覆盖已有用户记录。
- 记录日期、代码版本、模型模式、每步输入、实际结果、执行记录编号与失败原因。
- 使用真实模型前确认额度；离线或脚本化结果不能证明模型理解质量。
- 不把“模型说已完成”当成功：检查业务页面、持久记录及执行轨迹。
- 未完成或失败的项目保持未通过；不因为移除测试而清空已知问题。

| 日期及运动约束 | 明确“周三周四休息，只做力量训练，不跑步”，请求安排 | 计划日期和运动类型满足限制；约束不因摘要丢失 |
| 多领域协作 | 请求结合训练、饮食和恢复做复盘 | 展示子任务及证据；建议不越权修改业务数据 |
| 修改审批 | 请求调整已存在计划，先取消，再重新提出并确认 | 取消不写入；确认后只写一次；页面与执行回执一致 |
| 中断与回放 | 执行中刷新页面，再打开已保存执行记录 | 能恢复已记录事件；不重复发送模型请求或重复写入 |
| 账号隔离 | 使用另一验收账号访问前一账号记录 | 不能读取或修改其他账号的数据 |
| 工具及模型故障 | 在隔离环境模拟不可用服务 | 展示失败或未确认状态，不声称执行成功；保留错误线索 |
