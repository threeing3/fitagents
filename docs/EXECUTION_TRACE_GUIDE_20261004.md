# 执行追踪使用与实现边界

## 后台队列记录（2026-10-05）

实际执行者强制退出后，已通过真实网页服务重启读取验收：原应用路由和认证读取隔离数据库，本人可以查询，未登录、无效账号以及其他有效账号不能查询本人的记录。提交前和提交后对应的核对结果保持不同，读取不重复写计划。测试关闭生命周期迁移和知识初始化，未对完整启动过程或 PostgreSQL 部署作验收声明。

已验证实际审批减组处理器在四个阶段被强制终止后的持久结果。业务提交后、日志结束前退出时，日志仍为未确认，但计划提交凭据可以独立核对为已提交；不能把两者合并成一个成功或失败标志。后台追踪现在通过已验证的任务—审批关联带出提交凭据。验证使用隔离文件数据库和合成计划，不等同于完整部署验证。

前端“长期跟踪 → 审批与执行历史”现在可展开后台完整追踪，沿用只读历史面板与分页。审批历史接口仅返回与本人、当前任务及当前尝试明确关联的运行编号；不存在合法关联的旧记录不显示入口。页面载入时不自动读取完整追踪，展开后才读取；刷新记录不重新批准、不执行业务。此入口覆盖审批关联后台任务，不是全部后台任务的运维列表。

直接周期扫描另有运维汇总日志：责任唤醒和效果扫描记录开始、处理数量、提交返回及中断。扫描覆盖多个用户，因此不关联到任意单一用户，也不通过用户接口返回；只保存白名单中的汇总数量，不保存扫描的用户级返回结果。空扫描也保存记录，本轮不清理旧日志。提交返回与独立业务提交核对是两回事，提交后写日志失败仍标为结果未确认，不自动重新扫描。

每次领取提交后保存一个后台诊断运行。任务载荷中的 `execution_trace_run_id`（本次后台执行的追踪编号）指向该运行；运行节点保存任务编号和尝试次数。本人可使用已有追踪和事件分页接口读取，不能跨账号查询。

开始记录位于业务执行前，终止记录位于原业务及队列提交后；中间模型调用沿用受限记录器。后台诊断运行不同于处理器生成的业务执行运行，不能按运行总数判断业务写入次数。正常完成不替代独立提交核对。本地取消保留日志并传播取消，任务不会由追踪代码重新排队；任务可能仍标为运行中，需要后续核对。队列用户追踪不包含直接周期扫描的跨用户结果；完整应用硬退出恢复及全部后台任务运维列表仍未完成。

## 使用

正常聊天后，在回复旁展开“完整执行追踪”，再展开某一步，查看来源、时间、父/子任务编号、业务步骤、输入摘要和结果。面板底部可展开上下文与工具计划快照。审批后点“刷新记录”读取后续日志，不会重新执行工具。

新回复包含运行编号，重新打开历史会话后仍可关联。旧回复只有在已有运行保存了明确消息关联时才显示；不按时间或文本猜对应关系。没有记录的内容显示限制，不生成虚假的步骤。

## 数据路径

运行节点 / 工具记录 / 公开执行事件 / 审批日志 / 明确关联的子任务检查点
→ 已认证账号范围查询
→ 稳定编号去重、排序和敏感字段过滤
→ 只读追踪接口
→ 聊天内折叠面板。

真实模型请求的完整消息不是当前事件输入字段。界面的“已记录输入”是当时保留的摘要或受限片段，空对象表示没有保存，不表示模型没有输入。

## 参考与差异

[DeepSeek 官方架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)将持久会话事实、实时运行事件、历史投影分开，并要求模型可见输入从日志可重建。本版本实现统一记录查看和明确关联，但不是相同的完整会话事件运行时：

- 每个运行日志拥有源内顺序，不存在跨所有来源的全局顺序；页面按已记录时间生成展示序号。
- 子任务目录是检查点，只代表保存的状态，不补造之前每一步。
- 上下文可能已经截断，不能保证每次模型请求的精确复现。
- 主流程原有事务时机不变，进程突然崩溃时不能保证所有实时事件已经保存。
- 没有重新执行按钮，查看历史不会恢复有副作用的动作。
- 不展示模型隐藏推理，也不将模型公开说明当作工具执行结果。

实时事件现在携带稳定事件编号和本请求内的流顺序；正常结束时，将公开步骤、状态和工具事件补入当前运行，排除回复逐字片段，已有同编号节点去重。历史查看保留该流顺序，方便对应实时显示。缓存命中的原请求仍返回原保存事件，不新执行工具。顺序号是请求流内编号，不是所有后台任务的全局序号；断流或进程终止前尚未提交的事件仍可能缺失。

## 隐私

只供当前登录账号查看自己的记录；关联子任务还检查会话。隐藏推理和结构化密钥字段排除；限制长文本和大集合并标记截断。新模型调用事件可能包含应用指令及本人消息片段，这些属于本人诊断数据，不应未经清理公开发布。不会读取模型客户端配置中的密钥；不能保证用户主动写在自由文本中的任意敏感内容都被自动识别。

## 后续完整性工作

### 2026-10-05：逐事件持久前缀

公开事件现在在发给前端前写入独立追加文件并同步磁盘，不提交业务数据库事务。正常完成与捕获中断分别保存终止记录；硬退出缺少终止记录时，仅标记未确认，不能推断进程存活或工具结果。损坏尾行保留完整前缀并标记缺损，不修改原文件。

发生断流时，原请求的只读状态查询返回追踪编号，聊天可展开保存前缀；依然禁止自动重复执行。已经完成的运行显式关联日志，并在历史追踪中合并公开事件。回复逐字片段和模型隐藏推理不保存到此日志。

当前为本机文件持久化；不是多机器共享存储，也不包含所有工具执行前后的精确状态快照。取消测试与残留前缀测试不等同于真实进程强杀验收。数据库中的业务提交结果仍通过既有写入记录核对，日志中的“步骤完成”不替代这项核对。

若继续做到与上述官方事件架构同等级，应分开完成：实际模型调用入参与工具结果的受限记录、写入时机和崩溃恢复、按游标补齐实时事件、主子任务统一父步骤，以及相应故障验收。本次完成的是可用的已记录追踪入口，不能把这些后续能力写成已经验证。

### 2026-10-05：训练记录的独立提交凭据

训练写入结果新增提交凭据；历史追踪读取保存的工具调用时，会通过独立数据库连接重新核对原用户消息、会话归属、幂等完成凭据和实际训练记录。四者一致且完成时间存在，才能标记已提交。工具的成功状态仍保留，它与“本次读取是否确认提交”是不同信息。

核对连接暂时不可用、引用错误、记录归属不符或数据库仅有未提交状态时，显示未确认，不自动重复写入，也不改变调用事务。内存数据库无法可靠提供这种独立读取，明确返回不可核对。当前仅覆盖训练写工具的保存记录与原消息明确关联的中断请求；其他写工具及跨机器恢复不能据此宣称已覆盖。

前端展开工具事件，可查看结果里的凭据与解释。凭据是查询时对当前已提交状态的确认，不是不可变历史审计证书；未确认也不表示此前从未提交。

中断追踪页面顶部也显示训练写入的独立核对结果。它从已提交聊天请求的原消息关联出发，不信任日志中的成功声明，也不按相似文本猜记录。请求状态查询使用同一核对逻辑：业务提交可单独确认，但没有完整请求结果时整体仍为未确认；页面没有重跑入口。

### 审批计划调整的提交核对

明确关联的指定日期减组审批，在页面顶部展示独立核对结果。批准尚未执行不显示计划已更新；处于执行中或结果未知时，只显示业务写入未确认，不能推断未发生写入。

确认要求：审批已消费为执行完成、对应后台任务已完成且有提交时间、执行记录完成、责任事件明确关联同一审批与任务且属于同账号、结果目标和日期一致、当前计划等于批准草案。检查不重新执行工作器，不改变原事务。

如果计划后来被修改，当前草案一致性核对可能失败，这不证明历史执行从未成功。本功能是当前数据库状态核对，不是不可变的历史证书；仅覆盖该获批减组工具，不包含任意计划生成或自由修改。

### 按追加位置读取后续事件

展开完整追踪底部的“按位置读取后续事件”。第一次读取原追加日志，之后点“读取下一页”或“检查后续记录”，从上次完整位置继续，不重新执行工具。读取失败时保留已经显示的事件和恢复位置，重读不会重复展示相同位置。

位置属于一个明确日志，不是合并追踪的展示行号，也不是跨后台任务的全局事件编号。接口检查登录账号、会话、明确日志引用及日志头。错误或超过现存完整记录的位置被拒绝，不自动回退或猜测。

尾部缺少换行、编码截断或内容损坏时，只展示完整前缀，恢复位置不越过该部分；补完尾行后可以继续读取。终止状态与当前页是否还有后续记录分别返回，未核对进程存活。

这是单机文件的只读分页，仍需顺序扫描完整前缀；不是高性能随机访问、分布式共享日志或实时自动重连。完整追踪仍展示合并来源，增量面板单独展示原始追加顺序。

登录账号明确时，前端把账号、运行编号及读取位置保存在当前标签页存储中，刷新后重新展开会从已读位置续读，并提示仅显示后续记录。不会把事件正文、模型输入、健康数据或令牌复制进该位置存储；上方完整追踪仍可查看旧记录。切换账号或运行不使用原位置，旧账号迟到回复不会保存为新账号的位置。

浏览器存储不可用时继续正常只读查询，只是不保证刷新后保留位置。位置错误或服务器日志改变时不自动猜测恢复；点“从头只读查看”可以从开头重新读取，不执行模型和工具。位置是浏览器阅读偏好，不是认证凭据，也不是工作器恢复检查点。关闭标签页可能丢失位置，不提供跨设备或长期云同步。

### 模型调用的受限记录

聊天作用域中的常规聊天和意图客户端，记录实际回调边界的开始与结束。展开模型开始事件可查看消息角色、受限片段、工具定义和选定参数；结束事件保存公开内容、工具调用及可取得的用量。开始与结束按模型调用编号关联，每次重试拥有自己的编号。出错只记录异常类型，不保存可能包含敏感请求内容的异常文本。

图片只保留“已省略媒体”的标记，不保存地址或编码；模型推理块和响应中的额外推理字段不记录。开始事件写盘失败会阻止该次调用。只出现开始却没有结束时不能推断远端没有执行，整个请求的中断状态也不替代模型调用结果。

普通聊天和流式聊天都把追加日志明确关联到运行。流式入口只在处理内部下一事件时绑定模型日志，发给调用方后解除绑定；并发任务各自使用任务局部上下文。不在聊天日志作用域中的独立后台调用及图片接口尚未统一记录。

输入依然可能截断，部分消息结构和媒体被省略，因此不能精确重建全部网络请求。日志不是隐藏思考展示，也不证明模型判断正确；本轮验收使用本地假模型与真实回调协议，不是远端模型质量验收。

### 子任务的模型与依据读取

领域子任务和五角色复盘协作的模型事件，现在明确带父任务、子任务、领域、激活次数及模型轮次。事件展开后能看到步骤编号，按模型调用编号找到对应结束记录。来源在开始时保存，结束后沿用，不按最近的子任务猜归属；宿主继续调用模型时不会继承已结束子任务的来源。

实际只读查询也记录配对步骤：初次观察、接收模型建议前的依据重核对、协作交接重核对分别标记。结果保存受限的当前账号投影；失败只记录错误类型。写权限没有下放，模型要求非法写工具会被原校验拒绝，不会因此出现实际写入凭据。

这些观察片段是本人诊断数据，不应公开分享；长文本仍会截断。此改动让已执行步骤更可解释，不代表所有恢复和中断边界已经验收，也不证明多角色比单模型效果更好。

### 子任务中断及激活恢复

子任务状态转换直接追加生命周期事件，因此消费者关闭或父任务取消时，即使没有常规结果事件，也能保留本地终止原因。生命周期是运行时观察，不替代数据库提交凭据。

如果本地取消已发生但模型库没有结束回调，记录“本地等待已中断、远端结果未知”，关联原调用编号。不能据此宣称供应商已停止计算、未收费或模型执行失败。取消后不会启动后续领域；正常离线仍记录待执行到跳过，不伪造模型调用。

可继续模式保持同一子任务编号，以激活次数、版本和步骤区分新旧执行；恢复必须提交当前版本。旧版本被拒绝，不新增调用。该验收是本地协程取消和原运行时版本恢复，不等同进程硬退出后跨请求、跨机器恢复。

### 视觉与嵌入记录边界

已有日志作用域中的视觉客户端复用调用记录，图片只显示省略标记，不保存图片地址、字节或编码。不可用时显示跳过；模型完成返回只证明公开响应取得，不证明识别判断正确，也不代表已保存饮食记录。

嵌入记录输入字符数、原返回维度、适配后维度、逻辑查询耗时和向量是否取得。文本正文与向量省略，异常只记类型；失败和不可用仍按原逻辑返回无向量，由调用方决定后续降级，记录不冒充检索已经成功。开始记录写盘失败时不进入查询。

这里是一项逻辑调用的观察，不覆盖客户端内部每次网络重试。独立图片接口目前还没有建立日志作用域，不能仅因客户端装配了回调就声称图片业务全链路可追踪；独立后台业务同理。
# 独立图片识别记录（2026-10-05 补充）

通过图片校验的识别请求在模型调用前建立独立运行编号，响应增加 `agent_run_id`（执行运行编号）。本人可使用已有历史追踪与事件分页接口读取，无需聊天会话。诊断元数据使用独立事务，不提交调用方业务会话，不自动生成饮食记录。

正常识别完成不代表饮食已保存，也不证明识别内容正确。不可用或无有效解析结果记为未确认；异常和本地取消记录相应状态，仅保留异常类型。硬退出或终止记录失败留下可读前缀，日志状态仍为未确认，不自动重试。内存或共享单连接数据库不能保证此事务隔离，因此拒绝该路径。图片正文、地址及编码不进入模型追踪；当前没有前端饮食图片上传页面。
