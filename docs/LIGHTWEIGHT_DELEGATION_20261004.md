# 当前主链路：轻量分发 + 领域协作 + 统一执行控制

## 已落地的收敛

默认不再逐层运行四层意图分类。明确的单一请求由保守规则选择领域；复合、否定、引用和未覆盖表达由主路由一次模型理解输出任务集合。语义检索和 Jev（类型化决策模型）是显式选择的辅助能力，不配置不会阻塞运行。

这不是彻底删除已有意图名称：保留兼容的结构化契约，使上下文构建、领域委派和已有工具执行能够复用同一结果，而不是在每一步重新解释文本。

## 实际职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 轻路由 | 选择领域/宿主任务，保留复合请求涉及的任务 | 自动批准写入、生成最终建议、保证完整业务成功 |
| 训练/饮食/恢复子智能体 | 在主流程提供的账号范围内读取有效记忆和记录，给出结构化建议 | 任意读用户、直接写数据库、批准自己的建议 |
| 复盘协作 | 沿用证据分析与方案规划的交付闭环 | 用领域智能体替代已经做好的复盘分工 |
| 程序编排 | 复用本轮任务集合，选择已有受控工具与步骤 | 再调用一次模型规划相同请求 |
| 统一执行控制 | 风险下限、澄清、记录归属、审批、版本/幂等、写后检查 | 把分类分数或子智能体建议当作授权 |

明确记录、纠正、责任及确认仍沿用既有宿主确定性业务路径，不为了多智能体把每次保存也分给一个聊天角色。训练记录 + 饮食建议可以由宿主保存记录、饮食子智能体提供建议，而不是要求训练子智能体拥有写权限。

## 默认路径

1. 既有明确业务命令及会话确认路径优先处理。
2. 无副作用的分发判断：明确请求直接分发；其余至多一次主模型理解（默认没有额外分类器）。
3. 沿用风险下限、澄清和业务前置检查，不把分发当执行准备完毕。
4. 上下文构建和执行步骤复用同一任务契约；领域子任务按角色读取有效记忆，既有复盘机制不变。
5. 汇总建议；需要写入的动作仍由原宿主权限/审批/事务链路完成。

主模型不可用仍记录规则回退及澄清状态，不声明模型成功；默认不触发向量推理或模型下载。
“一次理解”限制的是主路由的重复分类/计划解释，不是整个对话只能调用一次模型。子任务分析与最终答复生成属于业务执行，仍有原有预算与失败处理。

## 保留的辅助与兼容

- 主引擎默认采用 DelegationRoutingPolicy（轻量领域分发策略）。
- 需要实验语义辅助时，显式注入 IntentCascadePolicy（语义候选级联策略）；64 示例与 62 验收题保留，不删除也不作为必经生产步骤。
- Jev 仅显式提供客户端时运行；没有新增密钥或付费调用。
- 旧适配器只有显式注入/已配置服务地址才调用；可选字段复核保留兼容，不是默认必经链路。
- 主模型的非风险任务集合不再与规则次意图无条件合并，防止已否定的任务重新出现。规则的真实风险判断仍保留。
- 运行方式从最终任务集合决定，不按消息中的“训练计划”等词语再次改写模型已经确认的分发。

## 可见轨迹

运行记录包含轻量路由模式、是否启用语义辅助、将选择的领域和权限归属。执行步骤以 TaskDispatch（任务分发复用事件）标记，不冒充一次新的模型规划。前端使用现有执行时间线展示这些事件和已有子任务状态，不新建独立演示页面，也不展示隐藏推理。

## 验证与范围

新增脚本化测试检查：明确请求零分类/向量调用，复杂多领域一次主理解后委派，否定不重新加入任务，风险不交给普通领域子任务，缺档案影响执行但不阻止只读领域选择，计划复用及模糊指代澄清。
主流程离线回放和审批、纠正、后台写入、工具权限边界同时回归。测试中的模型为受控替身，不能作为真实中文分发质量或线上收益证据。
原审批测试固定日期过期，本轮仅修正测试计划为用户时区的明后天；未来日期限制没有改动。
