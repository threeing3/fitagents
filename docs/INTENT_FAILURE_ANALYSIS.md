# FitAgent 意图适配器失败分析

## 结论

`field-calibration-dev-seed42-v4` 在 90 条独立 development 样例上完成真实 Qwen3-4B + Adapter 推理。当前模型不能直接接管意图决策：结构合法率、主次意图准确率、安全风险判断和置信度可靠性均未达到发布门禁。

线上链路必须继续采用“确定性风险规则 → 模型意图补充 → 字段级校验 → 规则回退/澄清”的分层架构。

## 数据与边界

- 数据集：`intent_dev_v1`
- 样例数：90
- 分区：development
- `training_eligible=false`
- 模型：Qwen3-4B + `full-800-seed42-v1` Adapter
- 置信度：生成 token 转移概率
- 本报告不使用冻结 test 调参，也不声明线上业务提升

## 聚合结果

| 指标 | 结果 | 判断 |
|---|---:|---|
| 结构合法率 | 85.56% | 未达到 99% 门禁 |
| 原始模型风险下限保持率 | 80.00% | 不可独立承担安全判断 |
| 主意图错误 | 41/90 | 需要新的分类基线 |
| 次意图错误 | 45/90 | 多标签识别是主要瓶颈 |
| 主意图高置信错误 | 20/90 | token 概率不可直接用于路由 |
| 次意图高置信错误 | 25/90 | 字段置信度明显失准 |
| 延迟 P50 | 3854.91 ms | 可用于复杂回退，不适合作为唯一前置分类器 |
| 延迟 P95 | 13446.31 ms | 无效长输出显著拉高尾延迟 |

## 失败分类

| 场景 | 样例 | 结构无效 | 主意图错误 | 次意图错误 | 风险失败 |
|---|---:|---:|---:|---:|---:|
| missing_parameters | 30 | 0 | 12 | 0 | 0 |
| multi_intent | 30 | 3 | 14 | 27 | 0 |
| safety_bypass | 30 | 10 | 15 | 18 | 18 |

### 1. 结构化生成失败

13 条输出无法解析为合法 IntentDecision，其中安全绕过场景占 10 条。无效输出平均延迟为 9786.15 ms，合法输出平均延迟为 4032.57 ms。模型在困难样例上更容易生成较长但仍不可解析的文本，因此“重试生成”必须受次数和 token 上限约束。

### 2. 多意图识别失败

multi_intent 的次意图错误达到 27/30，是最明确的任务瓶颈。当前“生成一个完整 JSON”把主意图、次意图、风险和澄清耦合在一次自回归生成中，一个字段的生成偏差会污染整个结果。

### 3. 安全绕过识别失败

18 条风险失败全部来自 safety_bypass。模型即使生成合法结构，也存在高置信风险误判。安全字段不能由 Adapter 单独决定，确定性规则必须执行风险等级 `max(rule, model)` 合并。

### 4. 置信度失准

主意图有 20 条、次意图有 25 条在字段置信度不低于 0.90 时仍然错误。生成 token 概率描述的是“模型对下一个 token 的确定程度”，不是“业务标签正确概率”，不能直接作为自动采用阈值。

### 5. 评测记录缺口

当前 `calibration_records.jsonl` 保存了字段是否正确，但没有保存预测的主意图、次意图、风险等级和澄清结果。因此本轮可以定位场景级失败，但不能构造完整混淆矩阵。下一轮必须补齐脱敏预测字段和解析错误码；继续禁止保存用户原文到公开报告。

## 技术决策

### P0：完善评测数据契约

逐条记录新增：

- `predicted_primary_intent`
- `predicted_secondary_intents`
- `predicted_risk_level`
- `predicted_needs_clarification`
- `parse_error_code`
- `fallback_applied`
- `retry_count`

产出主意图混淆矩阵、次意图逐标签 Precision/Recall/F1、风险分级混淆矩阵和结构失败类型统计。

### P1：约束结构化输出

为生成式 Qwen3-4B 增加 JSON Schema 约束解码：

1. 首次生成必须受 IntentDecision Schema 限制。
2. 结构失败只允许一次低 token 上限修复。
3. 第二次失败立即回退确定性规则，不继续消耗模型调用。
4. 分别记录首次成功、修复成功和最终回退比例。

发布门禁为结构合法率不低于 99%，且 P95 延迟不能因修复策略显著恶化。

### P2：建立判别式模型对照

新增共享编码器加四个任务头的判别式基线：

- 主意图：单标签分类
- 次意图：多标签分类
- 风险等级：有序分类
- 是否澄清：二分类

先实现 TF-IDF + Logistic Regression 的 CPU 下限，再实现中文语义编码器多任务模型。所有模型使用相同的用户级切分和固定 development/test，比较 Macro-F1、逐标签召回、风险 Recall、校准误差和延迟。

### P3：字段级路由

- 风险：始终使用规则与模型的较高等级。
- 主意图：只有通过独立校准器且预测稳定时采用模型。
- 次意图：逐标签设阈值，不使用一个整体置信度。
- 澄清：缺少必要槽位时规则可以强制要求澄清。
- 结构失败或超时：直接回退规则，不调用工具。

## 下一轮成功标准

- Schema-valid Rate >= 99%
- 风险规则合并后 Recall >= 98%
- 主意图 Macro-F1 >= 0.85
- 次意图逐标签 Macro-F1 有明确对照提升
- 高置信错误率显著低于本轮
- P95 延迟和回退率有完整记录
- 冻结 test 不参与阈值选择
